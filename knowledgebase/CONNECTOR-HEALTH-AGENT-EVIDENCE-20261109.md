# Agent connector-health diagnosis — 9 November 2026

Two independent defects affected the Google Drive health question:

1. `connector_list_apps` returned `connected: true` for an existing registration without health evidence. The agent-facing endpoint now includes owner-scoped historical health, its timestamp, explicit registration-only semantics, and a catalog-defined read-only live probe. It does not alter existing `connected` semantics or grant permissions. The final agent endpoint also performs bounded metadata probes when the caller already has an enabled execution tool, its tool/action grants, owner entitlement and policy permission. Unknown/unsupported/restricted/timed-out checks remain unverified; raw provider results are discarded.
2. Native run `f2234219-543d-4e5d-8ca6-532b819860de` attempted IDs such as `openclaw:agent-os-content-tools.connector_list_apps` and failed ten times before reaching any connector. Redacted traces confirm the same malformed namespace in the preceding user turns. The canonical catalog ID uses a colon before the tool name. The native resolver now supports this conventional separator variation only by exact comparison against visible catalog IDs. No fuzzy tool matching or guessed provider-action execution is introduced.

Existing exact IDs and literal names take precedence. Grant filtering, MCP exclusion, ambiguity rejection and normal argument/execution policy checks remain in place. Tests cover original installation, upgrade from the earlier `functions.` compatibility patch, repeat installation, both runtime/worker paths, wrong namespaces, misspellings and denied tools. Discovery, execution-policy, health-monitor, physical-single-dispatch, async-status and speech-routing regression tests passed.
