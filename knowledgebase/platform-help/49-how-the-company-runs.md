# How the company runs (architecture)

**Audience:** CEO. Same story as the public guide [How the company runs](https://flolah.cloud/docs/start/how-the-company-runs/).

You stay the **CEO**. Flolah is an **AI Company OS**: you give outcomes in plain language, the **COO** runs the company, named **AI employees** do the work, and you supervise on Kanban, Digest, and the bell.

| Surface | What you see |

## Operating model (read top to bottom)

1. **You** — Human CEO: decide, approve, teach the company.
2. **Direction** — Home chat (COO by default), scheduled goals, Broadcast, Company setup.
3. **COO** — Plan, match purpose, open Kanban, track. Keeps goals, standups, and status itself.
4. **AI employees** — Platform Help (how-to), Workflow Builder (graphs), CRM/ERP Maker then Checker, specialists (research, content, discovery).
5. **Systems they use** — Knowledge, Tools & Connectors, Workflows, CRM/ERP, Browser Session, channels — only what you granted.
6. **You see it** — Kanban, Digest / Workspace, bell, approval gates.

Work flows down. Visibility and approvals flow back up to you.

## Who to ask

| Need | Ask |
|------|-----|
| Get this outcome done | **COO** (Home chat, default) |
| How do I use Flolah? | **Platform Help** |
| Build or repair a workflow | **Workflow Builder** |
| Leads / pipeline | **CRM Maker / Checker** |
| Orders / books | **ERP Maker / Checker** |
| Recurring weekday outcome | **Scheduled goals** → COO |

Prefer one clear **outcome** per message. You do not need to pick a specialist first.

## Components and capabilities (layers)

| Layer | Meaning | Examples |
|-------|---------|----------|
| **L7 Experience** | Screens you open every day | Home, Digest, Workspace, My Org, Kanban, OEI, Virtual Rooms |
| **L6 Direct & supervise** | How work is assigned and watched | COO routing, scheduled goals, standups, Maker/Checker, approvals, bell |
| **L5 OS primitives** | Nouns of an AI-native company | People, Employees, Departments, Knowledge, Tools, Policies, Workflows, Tasks, Approvals, Memory |
| **L4 Capabilities** | What employees may do | Content tools, Connectors, MCP, Browser Session, CRM/ERP, Slack/WhatsApp/Voice |
| **L3 Compose & productize** | Repeatable services | Visual workflows, Workflow Builder, Job pipeline, AgentExchange, Windows package |
| **L2 Governance** | Isolation and control | Entitlements, API Keys / BYOK, policies, budgets, rate limits, IP allowlists, A2A Deny all |
| **L1 Runtime** | Platform under the company | AgentSystem, Flolah APIs, workflow runner, schedulers, tenant data, Knowledge search |

The unit of value is a **named AI employee** in your org, not a workflow node. Workflows compose a capability; AgentExchange offers it outward under your policy.
