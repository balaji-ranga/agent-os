## Generic implementation



- Resolve the exact WhatsApp reply target by native message identity, account, conversation and session. Recover it from bounded read-only native history after compaction. An unavailable explicit target requires clarification rather than guessed context.

- Classify current meaning using a typed semantic decision from the configured platform semantic-router model (the same primary routing role used by Dashboard). No user-text keywords select source, browser or scheduled execution. Cache the decision for the native turn, including compaction, and retain bounded trusted handoff context for asynchronous execution.

- Preserve browser executor constraints and the full user assignment at the API boundary. An explicitly selected executor cannot silently fall back without permission. Existing owner, connector, tool and mutation policies remain authoritative.

- Source identifier recovery and owner-local date selection are independent of the batching hint. Whole-period analysis uses bounded source review. Scheduled system work retains its existing registered scope and bypasses conversational intent classification.

- Use strict response schemas through both hosted and local transports. Invalid output, missing reply context or unavailable verification fails closed. One shared deadline bounds compatibility retries. Native call/token allowances include the new check; utility ledger entries are not charged twice.

- Browser completion is judged against the user goal, captured evidence and safety rules. Generated plan suggestions are excluded from acceptance authority. Optional unavailable links cannot create a false failure, while explicitly requested links and mutation receipts remain required.
