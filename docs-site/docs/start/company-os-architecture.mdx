# AI-native Company OS architecture

**Flolah is an AI-native Company Operating System that generalizes context, harness, loop and graph engineering beyond software development — enabling humans, digital agents and, eventually, physical agents to operate an entire enterprise through governed execution.**

The software factory builds software. **Flolah’s ambition is to build and run AI-native companies.**

## The execution architecture

The nested architecture below shows how the agentic business lifecycle contains graph, loop, harness and context engineering around the model layer. The Company OS foundation supplies identity, governance, agents and orchestration; integration and audit span the whole stack.

## How the layers work together

- **Model abstraction:** model selection, reasoning and tool calling provide capabilities to the operating system. See [models and API keys](../setup/api-keys.md).
- **Context engineering:** company roles, knowledge, master data and memory ground work in the organisation and current task. See [company knowledge](../setup/company-knowledge.md).
- **Harness engineering:** runtimes, MCP, connectors and tool grants provide controlled access to execution. See [connectors and MCP](../systems/connectors-and-mcp.md).
- **Loop engineering:** agents act, observe, verify and recover using recorded results, subject to permissions and budgets. See [how we loop](../operate/how-we-loop.md).
- **Graph engineering:** plans, routing, dependencies and workflows coordinate work across agents and systems. See [workflows](../systems/workflows.md) and [scheduled goals](../run/scheduled-goals.md).
- **Agentic business lifecycle:** humans set goals; the COO delegates to specialists; execution produces evidence for verification and review. See [how the company runs](./how-the-company-runs.mdx).

## Governed execution

Identity and entitlements determine whose records and connections are available. Policies and approvals determine which actions may proceed. Integration connects business systems; audit and work history record outcomes. See [policies](../systems/policies.md) and [budgets](../operate/budgets.md).

Humans and digital agents are central to this operating model. Physical agents are an extension of the ambition, with support dependent on adapters, equipment and local safety controls; see [physical AI scope](../systems/physical-ai.md). The architecture describes the design, not a guarantee of production reliability or support for every enterprise process.
