FloAssist: website onboarding and everyday use
Reviewed 25 October 2026 against the shipped FloAssist page and service.
Website: https://flolah.cloud
Setup page: https://flolah.cloud/free-tools/floassist/

What FloAssist is
FloAssist is Flolah's free personal assistant on WhatsApp, powered by the user's Flolah COO. It helps with email, calendars, files, reminders, morning briefings, priority alerts, calendar conflicts, deadlines and follow-ups, subject to connected apps and the user's effective Action Policies. It is not the Website Copilot: the Website Copilot explains this website and helps prepare onboarding fields; FloAssist handles the user's ongoing work through their COO and WhatsApp. Existing Flolah users should use their existing verified email and personal WhatsApp number to retain their COO. Everyday use does not require keeping the setup page or dashboard open. Optional dashboard access uses the verified email; the first password can be set through Forgot password by the user.

Step 1: Your details
Open Free Tools, then Set up FloAssist. Enter Email, Your personal WhatsApp number and Country. Email must be a valid address the user can access. Phone must use international format, such as a plus sign, country code and number; spaces, parentheses and hyphens are normalized. Country currently offers Singapore (SG), India (IN) and Indonesia (ID). Ask the user for missing real contact details; never invent them. The personal number receives messages. A different, dedicated WhatsApp number will be linked as the assistant's sender later. Using the same number for both roles is not allowed.
The user must personally review and accept the Terms, Privacy Policy and WhatsApp messaging consent, then choose Continue. Preparing contact fields is not consent or registration completion. Continue sends an email verification code. Do not repeat it after an uncertain response; inspect the current setup stage first.

Step 1 continued: Check your email
The six-digit Verification code and any Flolah authenticator code must be entered by the user directly in the website, never in copilot chat or shared knowledge. Existing accounts may require authenticator verification. The default email challenge lasts ten minutes and permits five attempts; expired challenges need Change details / resend. Verify and continue opens Your apps after successful verification. Change details / resend returns to contact details; the user then continues to request a new code. Authentication is not bypassed by the copilot or by choosing apps.

Step 2: Your apps
Select only the apps the user wants: Gmail, Google Calendar, Outlook Mail, Microsoft Calendar, Google Drive and OneDrive. Selecting a checkbox does not connect the account. Each selected, disconnected app has a Connect button. The user completes provider sign-in and OAuth consent in the provider tab, then returns and selects Check connections. No password, OAuth code or provider token should be put in copilot chat. A provider error or missing app configuration is not evidence of a successful connection. Microsoft Calendar availability depends on a supported configured provider; do not substitute Outlook Mail for calendar access. Users can deselect apps to add later. Activation requires every selected app to be connected. Do not claim to have connected an app from a checkbox or a Connect click alone.

Step 2 continued: Preferences and autonomy
Expand Preferences and autonomy to see responsibilities, Timezone, Morning briefing, Quiet from, Until and Autonomy. Responsibilities are Morning briefing, Priority alerts, Calendar conflicts, Deadline tracking and Follow-up tracking. Select the capabilities requested by the user; do not silently enable every capability. Select connectors appropriate to those capabilities, such as a calendar for calendar conflicts. Timezone is an IANA timezone; examples include Asia/Singapore, Asia/Kolkata, Asia/Jakarta, Asia/Makassar and Asia/Jayapura. Country does not establish which Indonesian timezone a user wants; ask if unclear. Time fields use local HH:MM. Equal quiet times mean no quiet hours; due reminders during quiet hours arrive afterwards. If the copilot cannot edit native time controls, guide the user to enter them on the website.
Autonomy defaults to Keep my current COO policy for existing users. New accounts start in Advisory. Advisory reads and proposes; Managerial manages work and asks before publishing; Administrative also covers financial and destructive actions. Choosing Administrative reveals Financial and destructive actions: Require my approval, Act autonomously or Do not allow. Changing autonomy updates the COO policy across Flolah, not just this setup page; task-specific policies still apply. Explain that effect and leave existing policy unchanged unless the user explicitly requests a change. Do not infer permission to increase autonomy from an onboarding request.
Continue to WhatsApp saves preferences and any explicitly selected autonomy changes, then opens WhatsApp linking. These controls can be hidden until verification or until Preferences and autonomy is expanded. Inspect the current visible stage before preparing changes. Hidden field definitions are guidance, not executable references.

Step 3: WhatsApp
On the phone holding the assistant's separate dedicated WhatsApp number, the user opens Settings, Linked devices, Link a device and scans the QR shown on the setup page. If onboarding is on the same phone, open setup on another screen to scan. Keep using the personal WhatsApp number to message the dedicated assistant number. The QR is a private authentication artifact: do not copy it to chat, knowledge or another visitor. Show / refresh QR retries linking. Start FloAssist stays disabled until the service confirms the linked dedicated number. After that the user can select Start FloAssist; activation checks the selected apps and creates or updates managed work. A visible QR alone does not prove pairing or activation.

Ready, pause and resume
After successful activation, Your assistant is ready and Open WhatsApp uses the confirmed linked number. Manage setup reopens apps and preferences. Pause checks pauses proactive checks; Resume checks resumes them. Pausing checks is not the same as disconnecting WhatsApp or revoking OAuth permissions. Sign out clears the setup session; it does not delete the account. Default verified setup access lasts two hours; verification may be required again after expiry. The ongoing assistant remains a server-side COO, not a browser automation tab.

Everyday examples and honest outcomes
Ask in WhatsApp: Remind me tomorrow at 9 to call Sam; What's on my calendar today; Summarize priority messages; Find a flight for my next trip. A reminder is scheduled only when a durable reminder receipt exists; a promise or timer-like chat response is insufficient. Payments, publishing, sending and destructive work follow the effective Action Policies. App authorization, real WhatsApp scanning, message delivery, reminders, booking and purchases need their own verified outcomes; website guidance alone does not certify them. FloAssist uses existing Flolah, WhatsApp and connector retention settings and does not promise zero retention.

Website Copilot guidance boundaries
The copilot may explain the stages, highlight the currently visible labels and prepare the contact details or preferences explicitly supplied by the user for review. It should fill available independent fields, ask about missing or ambiguous facts, and re-inspect after stage changes. Never invent a contact identity, accept legal consent for the visitor, read or fill verification codes, scan/copy the QR, approve OAuth permissions, change autonomy without an explicit request, or report registration/connection/activation as complete without the website outcome. Request human completion of those steps, then continue from the observed stage. Shared onboarding help contains structure and instructions only, never visitor values, codes, session credentials or QR contents.
