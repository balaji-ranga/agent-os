What changed

  • Read-only goal status checks preserve the pending DOM review. Unsaved-draft navigation is refused before approval/fence consumption; manual Save can be followed by a fresh review.
  • Continue / retry this step restores an unexecuted card. Approved effects require recorded-outcome checks and are never blindly replayed. Completed-step results are visible without a model call.
  • Independent known fields proceed while exact missing fields are asked for. Page examples and invented lookup identities cannot become transaction facts.
  • Native choice labels support paraphrased requests. Delayed select/radio dependencies are observed before dependent fills.
  • Large edits use the existing ten-action reviewed batches. Field reviews and goal assessments have separate checker verdict schemas; failed checks always override a contradictory accept.
  • Input admission is coordinated across planner, API, gateway, checker and internal reverse proxy. Exact duplicated refs and chat turns are removed while canonical facts and replies remain.

Configure the input ceiling

Default 60,000 bytes, range 16,000–128,000. This is a deployment setting, not an Admin UI control or a model output-token allowance.

ADOPTION_MODEL_CONTEXT_BYTES=96000

Set the deployment environment and recreate coordinator and model gateway together. Compose and the scoped installer apply it to both; the installer verifies equality. Gateway/API overhead allowance is 4,096 bytes. The edge ceiling is 132,096 bytes while the gateway enforces the actual lower configuration. The checker output budget remains 2,048 tokens and existing repair bounds are unchanged.

The observed complex request exceeded the former 32 KB edge guard. The reverse proxy, template and setup updater now agree. No new access, workflow entitlement, public submission, installation credential or laptop exposure was introduced.

Try the fix

  1. Refresh the local test tab once to load updated controls; do not clear browser storage.
  2. Choose Goal plan and ask: Fill Customer and Opportunity with sample values.
  3. After the Customer is filled, Save it on the website before leaving. If navigation was refused, use Continue / retry this step for a fresh approval.
  4. Use Check recorded step outcomes to see completed fills and pending work. A manual Save is not silently reclassified as a copilot Save receipt.
  5. For the large-form case, add native and complex controls and request sample values. Review the goal and each batch; unavailable existing-record identities remain explicit rather than fabricated.

Scope and limits

  • Real live cases use installed Chrome, the deployed configured maker/passive checker, the loopback host and public flolah.cloud. Only synthetic local records may be saved.
  • Browser regression uses explicit synthetic owners, policies, parsers and deterministic model fixtures; it is not proof of unseeded owner onboarding.
  • The workflow-after-goal browser regression is isolated connector delivery. This update does not recertify the signed-in Flolah workflow engine, fresh-owner DNS/email onboarding, or the deferred native-device matrix.
  • Source help/docs and build scripts are updated. A help-only shared-platform image/index publication is separate from this scoped coordinator/gateway release.
  • Model-only diagnostic replays are supplemental and not counted in the final live score. The six-case initial canary is historical evidence.
  • Higher input ceilings can raise inference cost for larger requests; no retry budget or action authority was increased. All-pass checks remain mandatory for acceptance.
