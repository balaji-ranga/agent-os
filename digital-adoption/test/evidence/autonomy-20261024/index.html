Approval required: complete visitor autonomy

5/5 live cases · 13/13 isolated browser cases · 0 failed · 0 partial

Unchecked now skips copilot approval prompts for user-requested plans, field changes, navigation, buttons and Save/submit. The setting stays with the same authorized tab session through ordinary navigation and reload. Checked remains the default for a new session.

Machine-readable matrix · Deployment and source verification

Behavior and boundaries

  • Requested goals start automatically and continue through verified effects without Start/Approve/Confirm clicks. Direct Save requests and recorded steps follow the same setting.
  • Actions and actual results remain visible. Autonomy does not invent a Save when the request asks only to fill.
  • Rechecking restores approval boundaries. The host checks the current setting before every effect and binds automatic approval to the current proposal ID.
  • Guide stays read-only. Invalid forms, stale targets, missing facts, denied policies and unknown outcomes stop the task; no automatic write replay is added.
  • Pairing, private-data sharing and browser permissions retain their explicit consent flows. Owner/server permissions and Flolah workflow Action Policies are unchanged.
  • Maker and checker receive the same conditional approval contract; they do not assume the application always pauses. No repair loop or model-token allowance was increased.

To use: reload once to load the updated browser code, open ⋮, uncheck Approval required, then send the task. Do not clear browser storage.

Earlier failure and recommendations

The first isolated run passed six cases, then Chrome rejected a synthetic routed document’s request to the loopback service because of address-space policy. This harness failure is retained in the original results. The corrected isolated harness passed all 13 cases; the deployed cases use normal Chrome with no address-space override.

  • Keep approvals checked for tasks where the visitor wants to review effects. Uncheck only when requesting autonomous execution.
  • Inspect uncertain host outcomes before retrying; the setting does not turn failures into automatic replays.
  • Keep long-session, low-end-device and paired-goal performance checks as separate follow-up measurements.

Scoped finite acceptance, not a statistical reliability guarantee or full Phase 1/2 certification.

Isolated browser cases use deterministic planner/auth fixtures and disable Chrome address-space checks only for synthetic loopback responses; normal Chrome is used for all deployed live cases.

No public form submission, new pairing consent, private-data sharing consent, real Flolah workflow-engine run or long-session performance soak was exercised in this incremental release. Existing workflow policy, revocation, action-fence and no-replay regression tests are included in the service suite.

Restored blocked/uncertain tasks are not automatically resumed; explicitly inspect or continue them.

The shared checker configuration, platform backend/frontend and parser workers were preserved.
